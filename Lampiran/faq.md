## Memilih Jalur

### 1. Aku harus memilih Python atau Java?

Jika masih ragu, pilih **Python**. Kemungkinan besar kamu sudah memakainya di mata kuliah pemrograman dasar sehingga energimu bisa dipusatkan untuk memahami konsep PBO, bukan bergulat dengan sintaks baru.

Pilih **Java** jika kamu ingin tantangan, ingin terbiasa dengan bahasa bertipe statis (tipe setiap variabel ditulis dan diperiksa sebelum program berjalan), atau tertarik ke bidang yang banyak memakai Java, seperti pengembangan aplikasi skala besar atau Android.

Apa pun pilihanmu, **konsep yang kamu pelajari sama persis**. Perbandingan lengkap kedua jalur ada di [Beranda](../README.md), bagian "Dua Jalur: Python dan Java".

### 2. Apakah aku wajib mempelajari keduanya?

Tidak. Cukup kuasai **satu** jalur dengan baik. Jalur yang lain adalah bonus.

Namun, kami sarankan kamu membaca halaman **Jembatan Python ↔ Java** di setiap pertemuan. Halaman itu singkat (sekitar 15 menit) dan membuatmu mampu membaca kode di bahasa lain. Kemampuan ini sangat berguna karena di dunia kerja kamu akan sering membaca kode dalam bahasa yang belum kamu kuasai.

### 3. Bolehkah aku pindah jalur di tengah semester?

Boleh, dan tidak perlu mengulang dari nol. Konsep yang sudah kamu pahami tetap berlaku. Yang perlu kamu pelajari hanyalah cara menuliskannya di bahasa baru.

Langkah yang disarankan:

1. Baca halaman **Jembatan** dari Pertemuan 02 sampai pertemuan terakhir yang sudah kamu ikuti.
2. Buka [*Cheat Sheet* Python ↔ Java](cheatsheet-python-java.md) untuk melihat sintaks penting berdampingan.
3. Kerjakan ulang beberapa latihan tingkat Dasar di bahasa barumu. Simpan hasilnya di folder latihan pribadimu, misalnya `PBO-latihan-saya/pertemuan-03`, bukan di folder materi.
4. Beri tahu dosen jika pilihan jalur memengaruhi ujian praktik atau proyekmu.

### 4. Bahasa apa yang dipakai untuk ujian dan proyek akhir?

Proyek akhir boleh dikerjakan dengan Python **atau** Java. Untuk ujian (UTS dan UAS), bentuk dan bahasa yang boleh dipakai mengikuti ketentuan dan pengumuman dosen pengampu. Jika ragu, tanyakan sejak awal semester.

## Tentang Materi

### 5. Kenapa *output* Python dan Java di studi kasus sama persis?

Program KedaiKita versi Python dan Java sengaja dibuat menghasilkan *output* yang identik, karakter demi karakter. Tujuannya:

- **Membuktikan bahwa konsepnya sama.** Dua bahasa yang berbeda bisa menghasilkan perilaku yang persis sama dengan rancangan yang sama.
- **Memudahkan perbandingan.** Saat membaca halaman Jembatan, kamu bisa fokus pada perbedaan cara menulis karena hasilnya sudah pasti sama.
- **Memudahkan pindah jalur.** Hasil yang kamu kenal dari satu bahasa bisa dipakai untuk memeriksa kode di bahasa lain.

Agar hasilnya benar-benar sama, materi ini menghindari hal-hal yang dicetak berbeda oleh kedua bahasa. Contohnya, nilai benar/salah tidak dicetak langsung (Python mencetak `True`, Java mencetak `true`), melainkan diubah dulu menjadi teks seperti "ya" atau "tidak".

### 6. Kenapa nama kelas dan *method* memakai bahasa Indonesia?

Ada dua alasan utama:

1. **Mudah dibedakan.** Saat membaca `hitung_total()` atau `Pesanan`, kamu langsung tahu itu buatan kita sendiri. Sementara itu, `print`, `append`, atau `ArrayList` jelas berasal dari bahasa pemrogramannya. Bagi pemula, pembedaan ini sangat membantu.
2. **Fokus pada konsep.** Kamu tidak perlu menerjemahkan istilah sambil memahami konsep baru.

Di dunia kerja, nama dalam bahasa Inggris lebih umum dipakai. Setelah konsepnya kamu pahami, berpindah ke penamaan bahasa Inggris sangat mudah.

### 7. Kenapa uang selalu memakai bilangan bulat?

Bilangan desimal (*float* atau *double*) di komputer disimpan sebagai **perkiraan**, bukan nilai yang persis. Kamu bisa membuktikannya sendiri tanpa membuat *file* apa pun.

**Python:** buka terminal, ketik `python` (macOS/Linux: `python3`) tanpa nama *file* untuk masuk ke mode interaktif. Setelah muncul tanda `>>>`, ketik baris berikut lalu tekan Enter. Keluar lagi dengan `exit()`.

```python
print(0.1 + 0.2)
```

**Java:** buka terminal, ketik `jshell` untuk masuk ke mode interaktif Java. Setelah muncul tanda `jshell>`, ketik baris berikut lalu tekan Enter. Keluar lagi dengan `/exit`.

```java
System.out.println(0.1 + 0.2);
```

Keduanya mencetak `0.30000000000000004`, bukan `0.3`. Penjelasan mode interaktif ada di [Instalasi Python](../00-Persiapan/instalasi-python.md) bagian 7 dan [Instalasi Java](../00-Persiapan/instalasi-java.md) bagian 8.

Untuk uang, selisih sekecil apa pun tidak bisa diterima. Karena rupiah tidak memakai sen dalam transaksi sehari-hari, KedaiKita menyimpan semua harga dalam **bilangan bulat** (`int`), misalnya `18000`. Perhitungan persen juga dibuat bulat, misalnya `harga * persen // 100` di Python atau `harga * persen / 100` di Java.

> [!NOTE]
> Aplikasi keuangan sungguhan yang membutuhkan pecahan biasanya memakai tipe khusus seperti `Decimal` di Python atau `BigDecimal` di Java. Materi ini cukup memakai bilangan bulat.

### 8. Kenapa program di materi tidak memakai emoji atau simbol khusus?

Konsol di sebagian komputer, terutama Windows, tidak selalu bisa menampilkan karakter di luar huruf, angka, dan tanda baca biasa (ASCII). Program bisa menampilkan simbol aneh, bahkan berhenti dengan *error*. Agar semua program di materi ini berjalan di semua komputer, kode dan *output*-nya hanya memakai karakter ASCII. Misalnya, panah ditulis `->`, bukan `→`.

Penjelasan teknis dan solusinya ada di [Mengatasi Masalah](../00-Persiapan/mengatasi-masalah.md), bagian A9 dan B10.

### 9. Kenapa harga di Pertemuan 02 tertulis Rp18000, lalu berubah menjadi Rp18.000?

Di Pertemuan 02, kita baru belajar kelas dan objek sehingga harga dicetak apa adanya: `Rp18000`. Mulai Pertemuan 03, kita membuat fungsi bantu `format_rupiah()` di Python dan kelas utilitas `Rupiah` di Java sehingga harga tampil rapi dengan titik pemisah ribuan: `Rp18.000`. Perubahan kecil seperti ini menunjukkan bagaimana aplikasi KedaiKita tumbuh dari pertemuan ke pertemuan.

### 10. Apakah soal di folder UTS dan UAS sama dengan ujian sungguhan?

**Tidak.** Repositori ini bersifat publik sehingga folder Pertemuan 08 (UTS) dan Pertemuan 16 (UAS) berisi **latihan persiapan** beserta pembahasannya. Soal ujian sungguhan disusun terpisah oleh dosen. Latihan itu tetap sangat berguna karena kisi-kisi dan tingkat kesulitannya disusun mengikuti materi.

### 11. Berapa lama waktu belajar untuk satu pertemuan?

Untuk kebanyakan pertemuan, kira-kira **3,5—4 jam**. Contohnya Pertemuan 02: 40 menit membaca konsep, 90 menit praktik, 15 menit jembatan, 60 menit latihan, dan 15 menit kuis, totalnya 220 menit. Pertemuan yang lebih padat, misalnya Pertemuan 13 dan 15, bisa butuh 4,5 jam atau lebih. Waktu untuk tugas mandiri belum termasuk.

Perkiraan waktu setiap pertemuan tercantum di tabel **Peta Belajar** di halaman konsepnya. Belajarlah sedikit setiap hari. Cara itu jauh lebih efektif daripada belajar semalam suntuk sebelum ujian.

## Latihan dan Solusi

### 12. Kodeku berbeda dengan solusi. Apakah kodeku salah?

Belum tentu. Dalam pemrograman, satu masalah hampir selalu bisa diselesaikan dengan banyak cara. Kodemu sudah benar jika:

1. ***Output*-nya sesuai** dengan contoh *output* di soal.
2. **Konsep yang diminta dipakai.** Misalnya, jika soal meminta enkapsulasi, atributnya memang dilindungi dan diubah lewat *method* yang memvalidasi.
3. **Kamu paham mengapa kodemu bekerja** dan bisa menjelaskannya ke orang lain.

Setelah kodemu berjalan, bandingkan dengan solusi. Tanyakan pada dirimu: "Apa yang lebih rapi dari solusi itu? Apa yang lebih baik dari kodeku?" Kebiasaan membandingkan seperti ini membuatmu cepat berkembang.

### 13. Kapan sebaiknya aku membuka solusi?

Bukalah solusi setelah kamu **benar-benar mencoba**, minimal 15—20 menit untuk soal yang sulit. Urutan yang disarankan:

1. Baca soal pelan-pelan, lalu tulis rencanamu dalam kalimat biasa.
2. Coba tulis kodenya di folder latihan pribadimu, misalnya `PBO-latihan-saya/pertemuan-04`. Jalankan, lalu perbaiki *error* satu per satu.
3. Jika buntu, buka bagian **Petunjuk** dulu.
4. Masih buntu? Buka solusinya, pahami, **tutup lagi**, lalu tulis ulang kodenya sendiri tanpa melihat solusi.

Membaca solusi tanpa mencoba terasa seperti paham, padahal belum tentu. Yang membuatmu bisa adalah proses mencoba.

### 14. Bolehkah aku memakai fitur bahasa yang belum diajarkan?

Untuk latihan pribadi, boleh asalkan kamu memahaminya. Namun, sebagian latihan sengaja dirancang untuk melatih konsep tertentu. Misalnya, latihan Pertemuan 02 sebaiknya tidak memakai pewarisan yang baru dibahas di Pertemuan 07. Untuk tugas yang dinilai dan ujian, ikuti ketentuan di soal dan arahan dosen.

### 15. Apakah aku perlu menghafal sintaks?

Tidak perlu menghafal semuanya. Sintaks yang sering kamu pakai akan teringat dengan sendirinya. Yang jauh lebih penting adalah memahami **konsep**: kapan memakai pewarisan, mengapa atribut perlu dilindungi, bagaimana objek saling bekerja sama. Saat lupa cara menulis sesuatu, buka [*Cheat Sheet* Python ↔ Java](cheatsheet-python-java.md). Ketentuan buka-tutup catatan saat ujian mengikuti aturan dosen.

## Bertanya dan Memakai AI

### 16. Bagaimana cara bertanya yang baik?

Pertanyaan yang baik membuatmu cepat mendapat jawaban yang tepat. Sertakan:

1. **Konteks:** pertemuan dan *file* mana yang sedang kamu kerjakan.
2. **Tujuan:** apa yang ingin kamu capai.
3. **Yang terjadi:** *output* atau pesan *error* yang muncul. Salin **teksnya**, jangan hanya tangkapan layar.
4. **Yang sudah dicoba:** langkah apa saja yang sudah kamu lakukan.
5. **Kode yang relevan:** potongan kode secukupnya, bukan seluruh proyek.

Contoh pertanyaan yang baik: "Di Latihan 1 Pertemuan 04, AC dengan suhu awal 40 tetap bisa dibuat, padahal seharusnya ditolak. Pemeriksaan batas 16—30 di *setter* `suhu` sudah bekerja saat suhu diubah. Berikut kode konstruktor dan *setter* saya: ..."

Sering kali, saat menyusun pertanyaan selengkap ini, kamu malah menemukan jawabannya sendiri.

### 17. Bolehkah aku memakai AI untuk belajar?

Boleh, **sebagai teman belajar**, bukan sebagai pengganti belajar. Asisten AI bisa membantu menjelaskan konsep dengan cara lain, membantu memahami pesan *error*, atau membuatkan soal latihan tambahan.

Yang **tidak** boleh: menyerahkan kode buatan AI yang tidak kamu pahami sebagai tugasmu, memakai AI saat kuis atau ujian tanpa izin dosen, dan menyembunyikan bantuan AI yang kamu pakai. Aturan lengkapnya ada di [Rencana Pembelajaran](../RENCANA-PEMBELAJARAN.md), bagian "Kejujuran Akademik dan Penggunaan AI". Kebijakan yang berlaku di kelasmu mengikuti ketentuan dosen pengampu.

### 18. Bagaimana memakai AI tanpa merugikan diri sendiri?

Beberapa kebiasaan yang membuat AI benar-benar membantumu belajar:

- **Minta penjelasan, bukan jawaban jadi.** Contoh: "Jelaskan arti pesan *error* ini dan kemungkinan penyebabnya, tetapi jangan perbaiki kodenya."
- **Minta petunjuk bertahap.** Contoh: "Beri aku satu petunjuk kecil untuk soal ini. Jangan beri solusinya."
- **Jelaskan kodemu ke AI**, lalu minta ia menanyakan bagian yang belum jelas. Cara ini melatih pemahamanmu.
- **Selalu jalankan dan periksa.** AI bisa salah dengan sangat meyakinkan, misalnya memakai sintaks yang tidak ada atau versi bahasa yang berbeda.
- **Uji dirimu tanpa AI.** Setelah dibantu, tutup percakapannya dan tulis ulang solusinya sendiri. Jika tidak bisa, berarti kamu belum benar-benar paham.
- **Cantumkan bantuan yang kamu pakai** di tugas yang dikumpulkan. Kejujuran itu dihargai.

Ingat, saat ujian dan presentasi proyek, yang diuji adalah kemampuanmu sendiri.

## Masalah dan Kesalahan

### 19. Program di materi tidak berjalan di laptopku. Apa yang harus kulakukan?

1. Pastikan kamu berada di **folder yang benar** dan memakai **perintah yang benar** (lihat [Menjalankan Program](../00-Persiapan/menjalankan-program.md)).
2. Periksa versinya di terminal: `python --version` (macOS/Linux: `python3 --version`) harus minimal 3.10, sedangkan `java -version` dan `javac -version` harus minimal 17. Lihat juga nomor 23.
3. Cari pesan *error*-nya di [Mengatasi Masalah](../00-Persiapan/mengatasi-masalah.md).
4. Pastikan kamu tidak mengubah *file* aslinya secara tidak sengaja. Jika materi kamu ambil dengan `git clone`, ketik `git status` di terminal dari folder `PBO2026` untuk melihat *file* mana saja yang berubah. Jika kamu mengunduh ZIP (folder `PBO2026-master`), unduh ulang ZIP-nya ke tempat lain sebagai pembanding.
5. Jika semua langkah di atas sudah dicoba dan program tetap gagal, mungkin memang ada kesalahan di materi. Laporkan seperti di nomor 20.

Agar *file* materi tidak berubah tanpa sengaja, lakukan semua percobaan di folder latihan pribadimu, misalnya `PBO-latihan-saya/pertemuan-05` (lihat [Git dan GitHub](../00-Persiapan/git-dan-github.md) bagian 5).

### 20. Aku menemukan kesalahan di materi. Bagaimana melaporkannya?

Terima kasih sudah teliti! Laporanmu membantu semua teman sekelas.

1. Buka halaman [Issues repositori](https://github.com/antonprafanto/PBO2026/issues), lalu klik **New issue**. Kamu perlu akun GitHub (gratis).
2. Tulis judul singkat, misalnya: "*Output* Contoh 03 Pertemuan 05 (Java) berbeda dengan README".
3. Di isi laporan, sebutkan:
   - ***file*** dan **bagian** yang bermasalah
   - **apa yang terjadi** dan **apa yang seharusnya terjadi**
   - **pesan *error*** dalam bentuk teks jika ada
   - **sistem operasi** serta **versi Python atau Java** yang kamu pakai

Tidak punya akun GitHub? Sampaikan langsung ke dosen atau asisten praktikum. Salah ketik kecil pun layak dilaporkan.

### 21. Aku tertinggal beberapa pertemuan. Mulai dari mana?

Jangan panik dan jangan langsung melompat ke pertemuan terbaru. Materi PBO saling bertumpuk, jadi:

1. Lihat [Peta 16 Pertemuan](../README.md) di Beranda untuk mengetahui apa saja yang terlewat.
2. Untuk setiap pertemuan yang terlewat, prioritaskan: **halaman konsep**, **studi kasus** di jalurmu, dan **latihan tingkat Dasar**. Bagian lain bisa menyusul.
3. Kerjakan **kuis** di akhir setiap pertemuan. Skor 8 ke atas berarti kamu siap lanjut.
4. Gunakan bagian **Mengingat Kembali** di awal setiap pertemuan untuk memeriksa apakah fondasimu sudah cukup.
5. Minta bantuan dosen atau asisten jika ada konsep yang tetap belum jelas.

### 22. Bolehkah aku memakai editor selain VS Code?

Boleh. IntelliJ IDEA, PyCharm, NetBeans, Thonny, dan BlueJ juga bisa dipakai. Petunjuk di materi ditulis untuk terminal dan VS Code, jadi sesuaikan sendiri cara menjalankan program di editor pilihanmu. Prinsip pentingnya tetap sama: untuk Java, buka folder `java/` milik satu pertemuan sebagai satu proyek. Lihat [Editor VS Code](../00-Persiapan/editor-vscode.md) untuk alasannya.

Satu hal yang perlu diketahui jika memakai VS Code untuk Python: Pylance, ekstensi pendamping Python, **tidak** memeriksa kecocokan tipe secara bawaan. Kesalahan tipe baru ketahuan saat program berjalan. Pemeriksaannya bisa dinyalakan lewat pengaturan **Python › Analysis: Type Checking Mode**, seperti dijelaskan di halaman praktik Python Pertemuan 10 dan 12.

### 23. Versi Python dan Java mana yang sebaiknya kupakai?

Semua kode di materi ini diuji agar berjalan di **Python 3.10 ke atas** dan **Java 17 ke atas**. Versi yang lebih baru juga aman dipakai.

| Bahasa | Minimal | Disarankan |
|---|---|---|
| 🐍 Python | 3.10 | 3.12 atau lebih baru (per Oktober 2026, versi terbarunya 3.15) |
| ☕ Java (JDK) | 17 | JDK LTS 21 atau 25 (JDK 25 adalah LTS terbaru) |

- **Python di Windows:** ikuti **Cara A: Python install manager** di [Instalasi Python](../00-Persiapan/instalasi-python.md), cara yang kini dianjurkan python.org. *Installer* klasik (Cara B, satu *file* `.exe` per versi) sudah dinyatakan usang sejak Python 3.14 dan tidak dibuat lagi mulai Python 3.16.
- **Java:** pilih versi **LTS** (*Long-Term Support*). Versi ini didukung lebih lama. Panduannya ada di [Instalasi Java](../00-Persiapan/instalasi-java.md).

Sudah memakai versi yang memenuhi syarat minimal? Materi tetap berjalan, jadi kamu tidak wajib memperbaruinya di tengah semester. Satu catatan: sejak 1 Oktober 2026, Python 3.10 sudah tidak mendapat pembaruan keamanan lagi. Jika masih memakainya, pertimbangkan memasang versi yang lebih baru saat ada waktu luang.
